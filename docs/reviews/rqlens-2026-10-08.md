# RQLens review — 2026-10-08

Baseline: `6d27e42`; tool: `../rust-quality-lens/target/debug/rqlens`
(SHA-256 `09b72768d645f97886ae4b22ced05553bbcac988fac290745e66f97405e94053`).
Both captures use the existing `rqlens.toml`, source roots and thresholds.
These are incremental improvements, not a claim that every requested metric improved.

## Findings and changes

- **Fast Pair repeated fixed-length validation and ANC mappings.** Battery,
  capability, ANC, address and PSM readers now reuse `decode_fixed` and destructure
  checked arrays. Error text, byte order and accepted lengths are preserved.
  ANC encoding/decoding share one mode table. Command construction borrows the
  reported state, releasing the read lock before asynchronous transport I/O,
  instead of cloning its strings and mode vectors.
- **Audio policy crossed the hardware boundary unnecessarily.** PipeWire policy
  application now lives in `audio::PolicyRequest`; BlueZ retains orchestration,
  retry deadlines and progress reporting. Both automatic policy and explicit API
  requests use `AudioDevice::available_profile`. This improves responsibility
  locality and intra-module reuse, but does not change the measured module graph.
- **Subscription setup maintained a redundant six-boolean mirror of stream names.**
  Validate against the protocol registry and share the existing forwarding macro
  between watch and broadcast sources. Removed `RequestedStreams` and `spawn_if`.
  Duplicate stream requests still produce only one forwarder. JSON audio payloads
  are moved into envelopes rather than serialized into another deep copy.
  Malformed/missing payloads retain their previous null projection.
- **Outgoing transfer setup copied state without needing separate owners.** Build
  the response before moving the queued event into the task; the progress callback
  borrows its event and sender. Transfer updates and D-Bus paths are borrowed.
  Reuse the API's typed backend-error envelope rather than assembling another one.
  Incoming event construction is local to its owner; its single-use seven-argument
  forwarding function is gone. Transfer ordering, cancellation and cleanup remain
  unchanged.
- **Operation events cloned on ownership transfer.** Move queued events into the
  active map after serializing the response, and consume cancellation events when
  changing state. Keep clones needed by independent progress/broadcast owners and
  keep the existing start barrier and terminal-result ownership checks.

No public Rust API or JSON contract was deliberately changed. No features were
removed as purportedly dead code. Compiler/Clippy checks find no dead-code warnings;
that does not establish reachability of every public API. Observed escape hatches
were already zero, so there is no numerical reduction to claim.

## Measurements

Production functions exclude module paths containing `tests` or ending in
`_tests` (a naming heuristic, not cfg-aware reachability). All-source line and clone
counts include tests; module means use the same 47 modules. Effort is RQLens's
Halstead heuristic, not developer hours or a runtime performance measurement.

Trade-offs: whole-source LOC reduction is only 15 lines because regression tests
consume most production savings; all-function effort increases. Module-level
locality/leverage are unchanged, despite reduced cross-module implementation
knowledge and shared selection logic. Token duplication increases by one: after
simplifying an error envelope, the detector groups the two consecutive OBEX
error-handling branches. Those branches deliberately retain different failure
codes and context. Clone-site counts are not allocation counts: necessary status
string copies remain when publishing owned transfer events. Unrelated ranking
functions still form the existing AST clone group; their policies should not be
combined merely to improve that metric.

## Validation and limitations

Passed:

- `cargo fmt --all -- --check`
- `cargo test --locked --all-features` — 65 tests, none ignored
- `cargo clippy --locked --all-targets --all-features -- -D warnings`
- Python quality-gate unit tests — 2 tests
- RQLens `measure all` and `verify` — zero error failures; four existing
  repository-documentation warnings

Regression coverage adds truncated/oversized fixed payloads, ANC flag round trips
and command rejection, scoped/available/active profile selection, nonempty and
malformed audio payload projection, supported/duplicate/mixed-invalid stream
validation, and outgoing/incoming transfer event projection equivalence. Existing
wire-fixture, cancellation, persistence and ownership tests remain intact.

Static evidence remains **partial**: seven item-macro invocations are unexpanded,
there are two unresolved lexical impl owners, and 19 dependency references remain
unresolved. Strict partial-evidence checks and the repository API-health quality
gate therefore still fail; no gates were relaxed. Macro-backed forwarding is not
fully inventoried, so syntax complexity reduction must not be read as elimination
of equivalent runtime branches.

The live sibling `daemon-framework` had concurrent edits during this review. One
measurement correctly refused to publish because inputs changed; it was rerun
successfully. The source metrics above concern this project's unchanged source
roots, but test/coverage results are observations in that live environment, not a
fully isolated dependency experiment. No sibling files were intentionally edited
by this refactor. Hardware, live D-Bus streams and allocation benchmarks were not
exercised, and no service was restarted.
