## Findings and refactors

- **OBEX monitoring duplicated lifecycle decisions.** Incoming and outgoing
  transfers now share subscription-before-refresh, property updates, acknowledged
  cancellation and terminal-error handling. Outgoing initial notification and
  session cleanup remain in the outgoing owner; incoming authorization and event
  formatting remain local. No transfer feature was removed as supposedly dead code.
- **Operation history deep-cloned full Bluetooth snapshots.** Terminal events now
  hold `Arc<Snapshot>`. Recovery snapshots serialize borrowed events, and completion
  consumes its event only after winning the active-request claim. Scan recovery
  likewise avoids cloning events solely to serialize them. JSON wire shape and
  caller-scoped cancellation are unchanged.
- **Audio identity leaked through the PipeWire profile parser.** Public audio key
  functions now live in `audio`, with unchanged hashes and public paths. Callers
  no longer depend directly on the parser. Sink/source slot selection is shared;
  the two one-off endpoint mutation wrappers are gone. Audio request metadata is
  grouped with its selector instead of separate forwarding functions. Snapshot
  construction borrows the pairing broker instead of incrementing Arc counts on
  every refresh.
- **Duplicated parsing and error projection.** Adapter/device operations share
  typed request parsing. Backend errors are constructed once as typed envelope
  details, not converted to JSON and immediately read back with fallback values.
- **Identity update allocations and unused plumbing.** Shared nonblank-text
  replacement retains missing/blank metadata; device-type strings are allocated
  only on change. Legacy identity migration moves matching map entries rather
  than cloning keys/values and looking them up again. Unused persistence-description
  arguments were removed. Battery component selection emits canonical components
  once in order, without allocating duplicates and then sorting/deduplicating.
- **Redundant asynchronous loops.** Suspend cancellation uses Tokio watch
  `wait_for`; BlueZ change forwarding reuses the framework broadcaster, preserving
  refresh-on-gap behavior and termination on channel closure.

The unrelated ranking functions flagged as an AST clone were deliberately left
separate: component ordering and device-type confidence are different policies.
The previously implemented Fast Pair readiness/retry logic is untouched.

## Measurements

These are advisory observations, **not complete verified static evidence**.
RQLens marks both captures partial because seven existing item-macro invocations
are not inventoried. Dependency identity resolved completely in both captures,
but that does not remove the macro limitation. Production function totals below
exclude modules named `tests` or ending in `_tests`; this is a naming heuristic,
not cfg-aware classification. Module averages use the same 47 modules.

Trade-offs are explicit: average observed-reuse leverage **decreases**, because
three consumers stop depending directly on the private profile parser. Audio
request locality improves from 97 to 100; its pressure falls from 45 to 42, and
operation-effects pressure falls from 47 to 44. Shared parsing/monitoring improves
code reuse within modules, which the module-level reuse metric does not count.

Production function SLOC falls by 131, but regression coverage offsets almost all
whole-source savings. Physical LOC is unchanged; this is not a substantial total
LOC reduction. There is no calibrated effort measurement here: complexity,
duplication and source size are proxies, not estimated developer hours. Clone-call
counts are syntax counts, not runtime allocation measurements. The compiler found
no dead-code warnings; removing redundant helpers and unused arguments is not proof
that every public API is reachable or needed.
