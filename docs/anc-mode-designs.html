Click a mode, or use arrows then Enter. Escape, × or an outside click cancels without changing the mode. Closing restores the preceding focus when appropriate.

Command → chooser, not a new form row

  • Closed: today’s layout, a subtle chevron on the existing mode artwork, plus the new secondary command. No extra vertical space.
  • Open: an overlay anchored to the battery row’s existing bounds. No height animation, card insertion or scroll jump.
  • Navigation: Left/Right (also Up/Down) move the candidate. Tab/Shift+Tab cycle inside the open chooser, matching menu traversal—not field-save behavior. Enter/Space selects. Escape discards.
  • Focus: the active mode is focused on entry. A check marks device-confirmed state; the focus outline marks the candidate. Browsing alone never sends a command.
  • Secondary command: register Noise control with accessKey: "C" in Shelllist’s shared action system. Scope it to the selected device’s available noise controls and respect modal guards. Show the C badge with the existing Alt-held hints, not permanently.
  • Small surfaces: fit the chooser inside the same hero bounds; adapt tile/image sizes or scroll horizontally rather than pushing Audio down.

State and lifecycle

  • Use the existing four labels and image assets: Ambient (transparent), Adaptive, Noise cancellation and Off.
  • Populate from reported available_modes; disable modes absent from settable_modes. Skip disabled targets during keyboard navigation.
  • On selection, close the tray and restore the battery row immediately. Keep the previous mode artwork until the provider confirms the change. Prevent duplicate requests while pending.
  • On failure, preserve reported state and show an explanation. Reopen with the same icon or Alt+C for an explicit retry.
  • On disconnect, device/tab change or loss of capability, close any unsubmitted chooser. Do not reopen it for a late response. Already submitted commands are not undone by dismissal.
  • The prototype shows shortcut badges continuously because the supplied screenshot already shows D/R/F. Production uses Shelllist’s existing hint timing.
